# QA round 1 — 2026-10-15

Scope: everything that can be exercised without the game client or HDT running — the CLI end to end, the MCP server
over stdio, the rule data against the **live** HearthstoneJSON catalog, and the Power.log tracker on the public
fixtures. Run on the maintainer's machine (Linux VM over `C:\Repos\DustPlanner`, .NET 10.0.402) and in the build
container.

## Method

| Step | What was done |
|---|---|
| Real catalog | `dustplanner catalog update` against api.hearthstonejson.com (build 255026, 8,328 collectible cards, 49 sets). |
| Realistic export | `.bench/qa/gen_qa_data.py` (git-ignored) builds a fake HDT export from the real catalog: 3,179 real dbf ids with plausible counts, goldens, copies above the playable limit, one copy in an unconfirmed premium slot, a saved in-game deck, an archived HDT deck, `rank.json`, and three deck codes encoded with python-hearthstone (Standard Priest, Wild Mage with United in Stormwind / Castle Nathria cards, saved Warlock). |
| CLI matrix | every command and sub-command, with and without `--json` (parsed back), every error path (no inbox, no database, bad deck code, unknown account, bad `--since`), deck as code / pasted block / file / stdin, `--locale esES` (real download), `--as-of`, `--dust`, `--account` by key and BattleTag. |
| Workflow | `sync` → `plan --need 500` (stored as #1) → collection edited by hand as if the plan had been followed (+1 pack opened) → `sync` → `history`: all four picks matched to plan #1 with **high** confidence, plan `confirmed`, the new card recorded as `gained / low`. |
| Games | three Power.log fixtures in dated session folders → `games import` (idempotent on re-run), `list`, `stats` with every filter combination. |
| MCP | hand-written JSON-RPC client over stdio: `initialize`, `tools/list`, every tool against the realistic home, error shape. |
| Tests | 115 automated tests green on both machines after the fixes. |

Not exercised here (needs the game / Windows desktop): the exporter plugin inside HDT (A1–A4 were ticked by the
maintainer), real Power.log files (C4), OBS (C5), `tools\package-exporter.ps1 -Install`.

## Findings

| # | Severity | Area | Symptom | Root cause | Fix |
|---|---|---|---|---|---|
| F1 | **High** | rules data | With the real catalog, every card from **United in Stormwind, Murder at Castle Nathria, Classic (EXPERT1) and Galakrond's Awakening** was "unknown craftability": missing copies not counted in `need`, owned copies never proposed in `plan`, warning on every run. HERO_SKINS and CORE_HIDDEN produced the same warning. | `data/non-craftable.json` was copied from python-hearthstone's `CardSet.craftable`, which omits STORMWIND and REVENDRETH (upstream gap) and never listed EXPERT1 / YEAR_OF_THE_DRAGON; the two non-card sets were not classified. | Added the four sets as craftable (sources in the file's `$comment_hand_added`: wiki.gg *Crafting* and *Galakrond's Awakening* pages) and HERO_SKINS / CORE_HIDDEN as non-craftable. CI keeps warning that they are hand-added. |
| F2 | **High** | MCP | `get_history` returned a tool error *"ExecuteReader can only be called when the connection is open"* as soon as the database held a snapshot. | The result object carried lazy LINQ queries (rank lookups, event projection) that ran during JSON serialisation, after `using var store` had closed the connection. The test only covered the "no snapshot" error path. | Materialise every payload inside the tool body; test now fills a snapshot, a rank sample and a plan and asserts the successful answer. |
| F3 | Medium | catalog | `catalog info` said *build latest*; the cache folder was `latest/` and a new game patch would never have been picked up automatically (the file existed, so nothing re-downloaded). | HearthstoneJSON stopped redirecting `/v1/latest/…` to `/v1/<build>/…` (CloudFront serves it directly); the build was only in the `/v1/latest/` directory index. | The provider reads the index (`/v1/(\d+)/` link) when there is no redirect; if the build is still unknown, a `latest` cache older than `MaxAge` is re-downloaded. Test added for the no-redirect behaviour. Verified live: cache now `255026/`. |
| F4 | Medium | tracker | Game times would be shifted by the local UTC offset (+2 h in Madrid) in `games list`, `--since` / `--days`, the overlay's *today* record and the MCP answers. | Power.log carries local wall-clock times; the parser stamped them as UTC. The tests only passed because CI and the VM run in UTC. | Parser, importer and follower take a `TimeZoneInfo` (default: the machine's zone). Fixture tests pass UTC explicitly; a new test checks Europe/Madrid. |
| F5 | Low | games stats | The per-class table ignored `--format` (overall said 1 game, the table 3). | `StatsByClass` had no format parameter. | Added; CLI and MCP pass it. Test added. |
| F6 | Low | need | `--as-of` beyond the estimated rotation (e.g. 2027-04-01) silently kept the 2026 Standard year. | No check that the data file still covers the date. | Warning when the as-of date is past the announced/estimated rotation and no later year is listed. |
| F7 | Low | plan | *NOT PROPOSED* listed a dust value for copies that are not craftable anyway (an EVENT card protected because it is in use showed "100 dust"). | "In use" exclusions computed the value without checking craftability. | Value is null unless the copy is craftable. |
| F8 | Low | CLI | `--account QaTester` was rejected although only `QaTester#1234` existed. | Exact match only. | Unique case-insensitive prefix of the BattleTag or key is accepted; ambiguous prefixes are reported. |
| F9 | Cosmetic | plan | "Excluded in total" split the same category by its text (`in use (2 in "X")` vs `in use (1 in "X")`). | Grouped by the full reason string. | Grouped by category, largest first. |
| F10 | Info | tooling | `HdtApiCheck` and `fetch-hdt-refs.ps1 -FromInstall` assumed the 1.55.6 executable name. | Installed 1.59.x builds ship `HearthstoneDeckTracker.exe`. | Fixed earlier today from the maintainer's own edit; both names accepted. |

Everything else behaved as documented: empty-state messages and exit codes (0 ok, 1 "no plan" / "not configured",
2 user error), JSON output valid and snake_case for every command, idempotent `sync` / `games import`, plan
matching, Spanish card names with `--locale esES`, stdin and pasted-block deck input, MCP annotations and error shape,
exporter inbox selection with several files present.

## Still open after this round

- **Exporter inside HDT**: only the maintainer can run it (A1–A4 are ticked; nothing new to add from here).
- **Real Power.log validation (C4)** and **OBS (C5)** — unchanged, see `VERIFICACION.md`.
- **Signature / diamond values (C2) and golden refund (C3)**: ticked in the checklist without the values; the code is
  still conservative (slots 2/3 excluded, golden refund "to verify"). Send the numbers and they go into
  `data/premium-slots.json` / `dust-rules.json`.
- `YEAR_OF_THE_DRAGON` craftability is sourced from the wiki, not from the game: if the crafting screen refuses a
  Galakrond's Awakening card, move the set to `non_craftable_sets`.
- Not reproducible here: whatever CLI problems the maintainer fixed locally before this round — the repository had no
  uncommitted changes when QA started, so they were either the `HdtApiCheck` ones (F10) or are not in the tree yet.
